# ARTBox iOS launcher

ARTBox has its own iOS application target, bundle, scene delegate, UIKit views
and original icon. It does not embed or launch another project's app. The root
screen is a searchable icon library; runtime logs are a separate navigation view.
The original geometric icon is generated by `scripts/generate_app_icon.py` and
uses no external artwork or package dependency.

Hello is the built-in runnable demo when the app is built with `--with-guest`.
Selecting it opens its output and executes both signed M1 packaging candidates.
The diagnostics button opens the startup log without automatically running them.

The plus button opens Files for an APK. ARTBox copies that file into its own
Application Support library, preserving a display name and using a random ID
for storage. A staged directory becomes visible only after both the copy and
metadata are saved. Duplicate filenames remain separate entries. A library
entry can be removed without modifying the original file in Files.

Import currently checks the file type and ZIP container header, not an Android
manifest, APK signature or package compatibility. It does not install or execute
the APK. Imported entries are labelled and explain that launching is unavailable.
No downloaded native code is mapped executable. Package metadata, real app icons
and launch readiness will be added with the Android package/runtime milestones.

The interface uses native Dynamic Type, VoiceOver labels, an adaptive grid and
semantic light/dark colors. `scripts/test_launcher.py` uses Xcode on macOS to
test Foundation storage operations and build a separate simulator app. UIKit
integration checks exercise the initial screen, search, Hello/log navigation,
the Files picker callback, persistence and layout. Two simulator sizes produce
screenshots in normal, dark and accessibility text configurations.

These checks invoke UIKit actions/delegates. They do not claim physical touches,
physical iPhone execution or Android execution in the simulator. The test hooks
are rejected for device builds and are absent from the transport IPA. The real
arm64 iOS 15 device build remains independently required in CI.
