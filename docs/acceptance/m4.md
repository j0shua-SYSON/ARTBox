## Observed behavior

The original service main and ServiceManager run unchanged. Manager, provider
and app client use separate Bionic PID/TLS, signed images, libbinder globals,
VM, descriptors and signal/thread owners. They share the portable Binder device.
The manager loop remains alive for the host process lifetime; this test does
not claim complete daemon shutdown or separate host processes.

The native provider registers a real BBinder through generated IServiceManager
proxies. The client finds its remote BpBinder, exchanges 32 ordered integer
payloads, and verifies trusted PID/UID despite forged identity words in payloads.
Unauthorized service addition/listing is denied. After the provider thread is
joined, descriptor close and receive-buffer unmap cause one original death
recipient callback. The dead proxy reports DEAD_OBJECT on a subsequent call.
Both finite role owners are cleaned up.

Separate processes pass Access results **20/-109/-107** for normal grants,
wrong client UID and wrong manager PID. Every process passes five original
VINTF policy-version checks. Unsupported policy fetching logs failure while
retaining its previous value; aggregate VINTF success is not SELinux support.

Independent artifact verification checks 36 Mac/iOS framework layouts,
372 notice hashes, seven corresponding-source inputs, 208 project files,
the native runner and all four retained process outputs. Device code is built
for iOS 15 with empty entitlements. This run does not execute it on a phone.

## Three largest next-milestone risks

1. Android Activity/framework boot requires substantially more original Java
   and native dependencies and real service contracts than this native fixture.
2. Surface/EGL/ANGLE integration must preserve signed-code and memory limits;
   no graphics or touch behavior is established by Binder acceptance.
3. Consolidating the retained native manager with ART introduces ownership,
   signal-handler and process-global interactions absent from separate diagnostics.
