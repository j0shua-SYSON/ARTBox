## What executes

NDK r28c builds the original libc-free static ARM64 ELF. On ARM64 macOS, both
signed candidates run through dyld and the real CPU: 100 invocations each,
exact hello output, exit 0, and exactly 100 calls to each of `write`, `exit`,
`mmap`, `mprotect` and `munmap`. A separate native check exercises the same
entry used by the UIKit console. No CPU interpreter or runtime code generation
is involved.

The native Linux ARM64 job runs the identical original ELF bytes, verifies its
hash against the Mac manifest, observes hello and exit 0, and verifies that
the bytes remain unchanged. The runner reports `mmap_min_addr=32768`.

Portable C tests pass on Windows/MSVC, macOS/Clang and Linux/GCC. The packaging
contract also checks instruction preservation, branch targets, container layout,
and fifteen malformed/unsupported-input rejection cases.

## Measurements

One newly started Mac host process per candidate, each executing 100 invocations.
The warm invocation includes all five syscalls and the host entry/exit bridge.
Load latency is one observation from before dlopen to the precompiled entry
bridge, not a statistically established difference. Process peak RSS includes
the complete host harness and libraries; it is not isolated guest memory.
Raw timing arrays and signed-file hashes are in the CI artifacts.

| Candidate | Signed Mac bytes | Median us | Min / max us | Load to entry ms | Process peak RSS bytes |
| --- | ---: | ---: | ---: | ---: | ---: |
| converted | 67,808 | 3.000 | 3.000 / 23.000 | 1.179 | 1,261,568 |
| wrapped | 51,456 | 3.000 | 3.000 / 20.000 | 0.978 | 1,245,184 |

The original image contains 193 bytes, of which
168 are instructions. Both routes use the same
964-byte transformed payload, including six SVC veneers.
The shared packer takes 0.282 ms on the Mac and
0.297 ms in the iOS build (one observation each,
excluding Python startup). Mac copy/link plus signing takes
26.597 ms for the converter and
555.875 ms for the wrapper;
the iOS build takes 28.787 ms and
947.131 ms respectively.
These one-off build timings include tool launch and signing work and do not
establish steady-state compiler performance.

The iOS framework sizes are 67,808 bytes for conversion
and 51,472 bytes for the wrapper. No iPhone timing or
ART interpreter performance is claimed. The wrapper is the preferred M2 basis:
Apple's linker owns container metadata, the signed output is smaller, and the
fixture shows no measured invocation penalty. The wrapper is selected for M2
with physical iPhone execution still unverified.

## Failures resolved

1. MSVC diagnosed a potentially uninitialized ELF section result; explicit
   initialization preserves the strict warning policy.
2. The initial Linux ELF linked at `0x4000` faulted before hello. Relinking at
   `0x10000` passed while the observed low-address guard is 32768 bytes. No host
   security setting or kernel behavior was changed.
3. The initial iOS post-build copy did not put frameworks in the final device
   bundle. Xcode's framework embedding phase now places them correctly; the
   artifact check verifies their presence, signatures and exact hashes.

## Three largest M2 risks

1. Dynamic Bionic needs ELF dependencies, relocations, symbol lookup and
   constructors beyond the controlled single-segment M1 input.
2. TLS, x18 and Android/Apple calling conventions require source-level bridges;
   signed machine code alone does not provide ABI compatibility.
3. Threads, futexes, files and mapping subsets must match Linux semantics before
   the dynamically linked NDK suite can meet the M2 coverage target.
