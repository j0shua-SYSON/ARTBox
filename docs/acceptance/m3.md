# M3 acceptance evidence

Real AOSP ART executes the hello DEX through signed ARM64 frameworks on macOS,
and the same runtime, DEX and console entry are embedded in an ordinary iOS 15
app. Full managed acceptance, both native Linux reference profiles and signed
device packaging pass. Physical checks are waived as milestone gates; a later
revision also passes on an iPhone 6s Plus, as recorded separately below.

## Required behavior

The signed process loads 15 images, returns from 38 constructors and creates a
real JavaVM on a Bionic pthread with checked stack bounds. Switch interpretation
is forced; JIT and profiling caches remain absent. Runtime executable mapping
requests remain denied. It invokes the original hello method and prints
`hello from ARTBox ART`, checks checksum 6496 after explicit collection, observes
three exceptions and completes four native attachment cycles with isolated TLS.
VM destruction succeeds, no registered VM remains and eight threads are reaped.

The actual guest-stdout callback captures hello and lifecycle completion. A
second process discards every console chunk and must fail that check with exit
3 after successful managed execution and cleanup. A third process omits hello
DEX, starts the VM and fails class lookup with exit 1. All three retained process
outputs and the 88-file corresponding-source bundle verify independently.

Both the original Linux ART reference and the adapted high-heap reference pass
the managed suite on native ARM64. Existing Bionic, fault, signal, syscall and
loader comparisons remain required. M2 retains its frozen 328/328 denominator.
Private futex requeue now supports ART's unchanged condition variables; its
separate wire caller and actual blocked-waiter tests pass against Linux.

## Signed device artifact

Independent archive inspection verifies **16 arm64 iOS 15 Mach-O images**,
15 original ELF/layout pairs, five runtime resources and **175 embedded notice
hashes**. Every image has a code-signature command and no W+X segment. CI checks
signatures with public `codesign --verify --strict`; entitlements are empty.
The shared logged ART entry is linked into the app. Staging pairs device code
with the executed Mac ELF and framework hashes and rejects incomplete acceptance.

The staging directory merges seven artifacts from that exact producer revision:
`bionic-startup`, `art-guest-link`, `art-math-diagnostics`,
`guest-loader-diagnostics`, `icu-guest-link`, `libcore-guest-link` and
`art-runtime-guest`. The required device job performs this download and staging;
a local rebuild must check out the recorded producer revision as well.

The console copies data to an owned app-container root and invokes that same
runner on a background queue. Its hello text comes from guest writes. This
establishes shared execution and device-target packaging; it does not establish
home-screen launch, background/relaunch behavior or iPhone memory usage. The
transport IPA needs ordinary provisioning of the app and all 15 frameworks.

## Measurements, failures and remaining scope

One traced Mac run at this revision creates the VM in **113.287 ms**. Load and
relocation take 85.288 ms; the 121.504 ms bootstrap/runtime phase includes VM
creation. Peak process RSS is **67,420,160 bytes**, and managed allocation before
shutdown is 636,072 bytes. These are single-run correctness observations,
not sustained interpreter throughput, console overhead or iPhone measurements.

Bring-up exposed initial-stack discovery, signal-34 delivery, virtual getcwd and
private futex requeue requirements. The worker stack and tested kernel subsets
resolve those failures; none of the managed acceptance checks was removed.
See ADRs 0085-0090 and the [earlier signed runtime evidence](../m3-signed-runtime.md).

M3 is interpreter-only. AOT/OAT, host dex2oat, repeated VM creation, general APK
loading, Binder, graphics and audio remain later work. The three largest M4
risks are isolating libbinder process globals for the manager and client;
enforcing a default-deny policy from trusted caller identity without a SELinux
kernel; and completing service/threadpool dependencies while preserving tested
Binder ownership and death-notification semantics.
